# P2 partial: variable-density two-phase 3D MAC pressure projection (02.11.2026)

## Implemented scope

A new **opt-in, standalone** finite-volume pressure projection solves for
both water and air on a full 3D staggered MAC grid. Unlike the existing
wet-only free-surface solver, **all cells** carry pressure and both phases
carry velocity. Each interior face uses the local arithmetic-mean density
and its reciprocal as the pressure mobility. Impermeable six-sided box
walls are enforced by rejecting nonzero prescribed normal velocities.
A Jacobi-preconditioned conjugate-gradient solve of the variable-coefficient
Neumann Laplacian uses a mean-zero pressure gauge. Its final residual is
recomputed from the solved pressure; input arrays are changed only after
the numerical and physical ledgers close.

The pressure step uses the consistent discrete equations

    u_next = u_old - dt / rho_face * grad(p)
    -div(grad(p)/rho_face) = -div(u_old)/dt

with the same face mobility in the Poisson matrix and the velocity
correction. It records a full-box mass inventory, divergence before/after,
and a **physically dimensioned** finite-volume momentum budget:
the pressure impulse on the fluid equals the integrated pressure
difference across opposing impermeable walls. For a closed box, the
discrete orthogonal projection satisfies

    E_before - E_after = (1/2) sum_faces rho_face * dV * (delta_u)^2

without treating numerical pressure projection loss as real viscous heat.
The ledger checks the difference explicitly. This is a constrained
incompressible two-phase pressure building block, not a compressible
air model or a complete free-surface Navier-Stokes solver.

## Native reproduction

Run only inside `D:\Projekt Engine`:

    Engine Core\UnifiedPhysicsCore\scripts\p2_two_phase_mac_pressure_build.cmd
    py -3 "Engine Core\UnifiedPhysicsCore\scripts\p2_two_phase_mac_pressure_acceptance.py"

MSVC/Ninja Release builds the new executable and all existing targets.
The new native suite uses three genuinely 3D grids: 4x3x3, 6x4x4,
8x6x5. Water/air density varies in x/y/z, with a sharp interface in x.
An analytic 3D polynomial pressure creates a known discrete gradient;
an independent nonzero divergence-free vortex is superposed. The
pressure step must recover the vortex, pressure modulo its gauge, close
wall impulse and energy, and remain idempotent. Separate native negative
cases reject nonpositive/nonfinite density, nonzero wall flux, malformed
fields, invalid timestep, and deliberately under-iterated PCG without
mutating the input.

The Python independent QA reconstructs the same physical reference
from separate equations, solves the 4x3x3 variable-density pressure
matrix by **pivoted dense Gaussian elimination** (not C++ PCG), checks
native pressure/velocity samples and divergence at all three grids,
reruns the native binary, rejects six altered traces, verifies full
CTest, official phase-gate and SHA-256 of code, binary and logs.

## Actual positive/negative evidence

The initial native MSVC Release build and full CTest passed:
**135/135 tests**, **2,651 assertions** in the new executable.
The initial three manufactured-grid pressure errors were
1.59e-11 / 1.41e-10 / 1.79e-10 Pa, and maximum post-projection
divergences were 7.27e-13 / 7.96e-12 / 1.74e-11 s^-1.
The full audit/report is generated by the independent Python QA in
`ENGINE TEST STUBE/runs/p2_two_phase_mac_pressure_partial.json`,
with source and artifact SHA-256 and negative fixture results.

**Explicitly not validated:** the new projection is **not yet wired
into the live moving VOF/PLIC solver**, does not include a moving
air-water interface with stress/normal-jump conditions, capillarity,
dynamic two-way FSI, or actual MARIN H1-H4/P1-P8 experimental matching.
The historical full-6s MARIN/SPHERIC case still misses the 0.05 m
water-height RMSE limit; its independent pressure measurements and
three-grid convergence remain open. No expensive 6s run was repeated
to manufacture an improvement. No new UE5.8 Native E2E was run.

**P2 is PARTIAL.** A successful bounded pressure-projection test is
not a P2 full-phase acceptance. The official `phase_gate.py` retains
P2 in `full_acceptance_open` until the independent measured/native
E2E requirements are actually fulfilled.

## Independent QA negative finding (preserved)

The first Python QA run correctly **failed** its deliberately corrupted
`div_after` fixture: adding a digit to the prefix of a very small
residual still left a value below the strict tolerance. This was a QA
fixture error, not a native solver failure. The fixture now replaces the
entire numeric field with `9`; all six independent corruption cases
must be rejected before the partial report is accepted. The failed QA
attempt was not counted as a successful acceptance.

The official gate may mark older P1 prototype evidence PARTIAL after
CMakeLists.txt changes because historical P1 report source hashes no
longer match. Do not silently rewrite old P1 hashes or claim a P1
regression failure without rerunning its original full acceptance.
